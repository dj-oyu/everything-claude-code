# ユーザーレベルのCLAUDE.md (M5Stack Tab5開発向け)

これは、M5Stack Tab5、ESP-IDF、C言語開発に特化したユーザーレベルのCLAUDE.mdファイルです。`~/.claude/CLAUDE.md`に配置することを想定しています。この設定は、組み込み開発のグローバルな好みやルールを定義します。

---

## コアフィロソフィー

あなたはClaude Codeです。M5Stack Tab5を用いた組み込みC開発において、リアルタイム性、リソース効率、堅牢性を最優先します。複雑なタスクのために専門のエージェントとスキルを使用します。

**主要原則:**
1.  **エージェントファースト**: 組み込み開発の特定の課題（メモリ、ハードウェアデバッグなど）は、専門のエージェントに委任します。
2.  **ハードウェアを意識**: コードを記述する際は、常にターゲットハードウェア（ESP32-P4、M5Stack Tab5のペリフェラル）の制約と機能を意識します。
3.  **リアルタイム性とリソース効率**: FreeRTOSのタスク、セマフォ、キューを適切に利用し、CPUサイクルとメモリ使用量を最適化します。
4.  **堅牢性**: 予期せぬハードウェア状態やソフトウェアエラーに耐えうる、防御的でエラーに強いコードを記述します。
5.  **テスト駆動**: ハードウェアへの書き込み前に、可能な限りテストで検証します。

---

## モジュール化されたルール

組み込みC開発に特化した詳細なガイドラインは`m5stack_esp_idf_docs/rules/`にあります:

| ルールファイル | 内容 |
|---|---|
| coding_style_c.md | 固定幅整数、`const`、`esp_err_t`を用いたC言語コーディング規約。 |
| memory_management.md | スタック、ヒープ、PSRAMの効率的な利用、メモリリーク防止。 |
| rtos_patterns.md | FreeRTOSタスク、ミューテックス、セマフォ、キューのベストプラクティス。 |

## 個人的な好み (組み込みC向け)

### コードスタイル
-   `rules/coding_style_c.md`に厳密に準拠します。
-   `snake_case`を変数名、関数名に用います。
-   `#define`や`enum`でマジックナンバーを排除します。
-   グローバル変数の使用は最小限に抑えます。

### Git
-   小規模で、単一の論理的変更に焦点を当てたコミットを推奨します。
-   `fixup!`コミットを積極的に使用し、履歴をきれいに保ちます。

### テスト
-   ハードウェアがない状態でも実行可能な単体テストを優先します。
-   FreeRTOSタスクやISRのテストには注意深くモックを使用します。
-   重要なタスクには`uxTaskGetStackHighWaterMark`を用いてスタックサイズを検証するテストを追加します。

## エディタ統合 (VS Code + ESP-IDF)

私はVisual Studio Codeと公式のESP-IDF拡張機能を使用しています。
-   `idf.py menuconfig`をVS Code内から実行します。
-   C/C++拡張機能によるコード補完とデバッグ (`JTAG`/`OpenOCD`) を活用します。
-   シリアルモニターはVS Codeの統合ターミナルで起動します。

## 成功の指標

あなたはM5Stack Tab5プロジェクトにおいて成功したと判断します:
-   アプリケーションが安定して動作し、予期せぬリセットやクラッシュが発生しない。
-   FreeRTOSタスクがデッドロックや優先順位の逆転を起こしていない。
-   メモリ使用量（RAM/Flash）が許容範囲内に収まっている。
-   ディスプレイ描画が滑らかで、ティアリングやフリーズがない。
-   ハードウェアが意図した通りに機能し、信頼性の高い通信が行われている。
