# マイコンでのハイパフォーマンスレンダリングスキル

このスキルは、ESP32-P4を含むマイコンにおけるハイパフォーマンスなグラフィックレンダリングをAIエージェントが最適化するための指針を提供します。動画再生、アニメーションUI、リアルタイムデータ表示など、高いフレームレートと滑らかな表示が求められる場面で活用します。

## コア原則

*   **ハードウェアの最大限活用**: 専用のIPコア（JPEGデコーダ、PPAなど）を優先的に使用します。
*   **メモリ帯域の最適化**: データ転送回数やデータ量を最小限に抑え、PSRAMなどの外部メモリ帯域のボトルネックを回避します。
*   **描画同期**: ディスプレイのリフレッシュレートとレンダリングを同期させ、ティアリングを防止します。

## 主要テクニックとパターン

### 1. ハードウェアアクセラレーションの活用

*   **HW JPEG Codec (`esp_driver_jpeg` / `esp_new_jpeg`)**:
    *   **目的**: 高解像度画像の高速デコード。ソフトウェアデコードと比較して60fpsでの安定描画を実現。
    *   **方法**: ESP32-P4などのSoCに搭載された専用IPを使用。Espressifが提供する最適化されたJPEGライブラリ（SIMD命令利用）と組み合わせることで、中間バッファを介さず直接フレームバッファに書き込む最適化が可能。
    *   **M5Tab5サンプルコードからの示唆**: `bsp_display_new_with_handles`関数内でMIPI DSIバスとLCDパネルが初期化されており、`ili9881c_vendor_config_t`や`st7703_vendor_config_t`などディスプレイコントローラ固有の設定がJPEGデコード結果の表示パスに影響を与える可能性がある。

*   **PPA (Pixel Processing Accelerator) の利用**:
    *   **目的**: 画像の回転、拡大縮小などの変換処理をCPUからオフロード。
    *   **注意**: JPEGデコーダとPPAを同時に使用すると、PSRAMの帯域がボトルネックになる可能性があるため、慎重な設計が必要。

### 2. 描画品質とティアリング対策

*   **ダブルバッファリング**:
    *   **目的**: 画面のティアリング（描画途中の画像が表示される現象）を防止し、滑らかな描画を実現。
    *   **方法**: 2つのフレームバッファを交互に使用。デコーダは非表示のバッファに書き込み、描画完了後に表示バッファを切り替える（フリップ）ことで、一貫したフレームを表示します。
    *   **M5Tab5サンプルコードからの示唆**: `lvgl_port_add_disp_dsi`関数の`disp_cfg`で`.double_buffer = cfg->double_buffer`が設定可能であり、LVGLが提供するダブルバッファリング機能を利用している可能性が高い。

*   **リフレッシュレートの調整**:
    *   **目的**: ディスプレイの推奨リフレッシュレート（例: 60fps）に合わせ、描画と表示の同期を改善。
    *   **方法**: `dpi_clock_freq_mhz`、`lane_bit_rate_mbps`などのMIPI DSIパラメータを調整。
    *   **M5Tab5サンプルコードからの示唆**: `esp_lcd_dsi_bus_config_t`の`lane_bit_rate_mbps`や`esp_lcd_dpi_panel_config_t`の`dpi_clock_freq_mhz`が設定されており、ST7123の場合965Mbpsと70MHzが使われていることが示されている。

*   **True Color (RGB888) の利用**:
    *   **目的**: より豊かな色彩表現。
    *   **注意**: RGB565（16ビットカラー）と比較してフレームバッファのデータ量が増加し、フレームレートが若干低下する可能性があるため、画質とパフォーマンスのトレードオフを考慮。
    *   **M5Tab5サンプルコードからの示唆**: `lvgl_port_add_disp_dsi`関数の`disp_cfg`で`LV_COLOR_FORMAT_RGB888`または`LV_COLOR_FORMAT_RGB565`が選択可能。

### 3. その他の最適化

*   **直接フレームバッファへの書き込み**:
    *   **目的**: データ転送オーバーヘッドの削減、描画速度の向上。
    *   **方法**: 中間バッファ（例: `M5Canvas`のようなライブラリ内部の描画バッファ）を介さず、デコード結果を直接ディスプレイのフレームバッファに書き込みます。
    *   **M5Tab5サンプルコードからの示唆**: `esp_lcd_panel_ili9881c`や`esp_lcd_panel_st7123`などのLCDパネルドライバーは、直接フレームバッファにアクセスする機能を提供している可能性があり、LVGLなどの高レベルライブラリを使用しない場合はこのパスを検討。

*   **キャッシュ管理**:
    *   **目的**: 静止画表示後のメモリ操作など、特定のユースケースでのデータ整合性確保。
    *   **方法**: 必要に応じて明示的なキャッシュフラッシュ (`esp_cache_flush_...`) を実行。

## 性能最適化チェックリスト

*   [ ] ディスプレイコントローラに最適なMIPI DSIレーンビットレート (`lane_bit_rate_mbps`) とDPIクロック周波数 (`dpi_clock_freq_mhz`) を設定しましたか？
*   [ ] 高速な画像デコードが必要な場合、ハードウェアJPEGデコーダを使用していますか？
*   [ ] ティアリング防止のためにダブルバッファリングを有効にしていますか？
*   [ ] 中間バッファリングを最小限に抑え、可能な限り直接フレームバッファに書き込んでいますか？
*   [ ] 画像変換処理にPPAを利用していますか？また、その際にPSRAM帯域のボトルネックを考慮していますか？
*   [ ] RGB888（True Color）の必要性を再評価し、RGB565で十分な場合はそちらを選択していますか？
*   [ ] LVGLなどの描画ライブラリの設定で、DMA転送やSPIRAMバッファリングを適切に利用していますか？

## いつこのスキルを使用するか

*   M5Stack Tab5で動画再生機能や複雑なアニメーションUIを実装する場合。
*   グラフィック表示のフレームレートが低い、またはティアリングが発生している場合。
*   ディスプレイ関連の処理がCPU負荷のボトルネックになっている場合。
*   新しいディスプレイドライバーやグラフィックライブラリを統合する場合。
*   ディスプレイの描画品質とパフォーマンスのトレードオフを評価する場合。
