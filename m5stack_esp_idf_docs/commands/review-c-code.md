# review-c-codeコマンド

このコマンドは、現在のコード変更点（コミットされていない変更や指定されたファイル）に対して、組み込みC言語開発に特化したコードレビューを実施します。`coding_style_c.md`、`memory_management.md`、`rtos_patterns.md`のルールを適用し、品質、信頼性、リソース効率に関する問題を特定し、修正を提案します。

## このコマンドの機能

1.  **コーディング規約の遵守**: `m5stack_esp_idf_docs/rules/coding_style_c.md`に定義されたC言語のコーディング規約（固定幅整数、`const`の活用、エラーハンドリングなど）に照らしてコードを評価します。
2.  **メモリ管理のレビュー**: `m5stack_esp_idf_docs/rules/memory_management.md`の指針に基づき、メモリリークのリスク、不適切なヒープ割り当て、スタックオーバーフローの可能性、`heap_caps`の適切な使用などをチェックします。
3.  **FreeRTOSパターンの適用**: `m5stack_esp_idf_docs/rules/rtos_patterns.md`に従い、タスクの設計、同期プリミティブの誤用、デッドロックや優先順位の逆転の可能性などを評価します。
4.  **問題点の特定と提案**: 検出された問題点について、具体的なコード例や修正提案を提示します。

## 使用する場面

*   新しいC言語コードを記述した後、コミットする前。
*   既存のコードを修正またはリファクタリングした後。
*   重要なドライバやFreeRTOSタスクを実装した後。
*   メモリ使用量やリアルタイム性に影響を与える可能性のある変更を行った後。
*   チームメンバーのプルリクエストのレビュー時（シミュレーション）。

## 仕組み

1.  **レビュー対象の特定**: `git diff HEAD`でコミットされていない変更点を取得するか、ユーザーが指定したファイルを対象とします。
2.  **ルールの適用**: C言語コーディング規約、メモリ管理ルール、FreeRTOSパターンのチェックリストを適用します。
3.  **詳細なフィードバック**: 各問題について、関連するルールへの参照、発生箇所、具体的な修正例を含めたフィードバックを生成します。

## 使用例

### コミットされていない変更点をレビューする

```
/review-c-code
```
エージェントは、現在のワークディレクトリにおけるコミットされていないすべてのC言語コードの変更点をレビューします。

### 特定のファイルをレビューする

```
/review-c-code main.c
```
```
/review-c-code components/display_task/display_task.c
```

### レビューの詳細度を指定する

```
/review-c-code --severity HIGH "components/sensor_driver/"
```
この例では、`components/sensor_driver/`ディレクトリ内のコードについて、重要度が高い問題に絞ってレビューします。
