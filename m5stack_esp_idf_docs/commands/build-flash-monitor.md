# build-flash-monitorコマンド

このコマンドは、`build-flasher`エージェントを呼び出し、ESP-IDFプロジェクトのビルド、ファームウェアのデバイスへの書き込み（フラッシュ）、およびシリアルモニターの開始という一連のプロセスを管理します。

## このコマンドの機能

1.  **プロジェクトのビルド**: ソースコードをコンパイルし、ファームウェアバイナリを生成します。
2.  **ファームウェアの書き込み**: ビルドされたファームウェアをシリアルポート経由でESP32に書き込みます。
3.  **シリアルモニターの開始**: デバイスからのシリアル出力を表示し、実行時のログを監視します。
4.  **エラーの自動診断**: ビルドエラーや書き込みエラーを診断し、解決策を提案します。

## 使用する場面

*   ESP-IDFプロジェクトの通常の開発サイクル。
*   コード変更後にデバイスにファームウェアをデプロイし、動作をすぐに確認したい場合。
*   ビルド、書き込み、モニターの各ステップを個別に実行する手間を省きたい場合。

## 仕組み

`build-flasher`エージェントは、以下のステップで動作します。

1.  **ビルドフェーズ**:
    *   `idf.py build`を実行します。
    *   ビルドが成功した場合、RAMとFlashの使用状況（`idf.py size`の結果）を報告します。
    *   ビルドが失敗した場合、コンパイラのエラーメッセージを解析し、問題を特定して解決策を提案します。必要に応じて`build-error-resolver`エージェントに委任することもできます。
2.  **書き込みフェーズ**:
    *   ビルドが成功した場合、`idf.py flash`を実行します。
    *   書き込みが失敗した場合、シリアルポートの接続問題、パーミッションエラー、デバイスがブートローダーモードになっていない可能性などを診断し、解決策を提案します。
3.  **モニターフェーズ**:
    *   書き込みが成功した場合、`idf.py monitor`を開始します。
    *   デバイスからのログ出力を監視し、`Guru Meditation Error`や`assert`などの致命的なエラーが発生した場合は、その内容をユーザーに報告します。

## 使用例

### 基本的な使用法

```
/build-flash-monitor
```
シリアルポートが一つしかない場合は自動で選択されます。複数ある場合は選択を求められます。

### 特定のシリアルポートを指定する場合

```
/build-flash-monitor --port /dev/ttyUSB0
```

### ビルドのみ実行する場合

```
/build-flash-monitor --build-only
```

### 書き込みとモニターのみ実行する場合 (既にビルド済みのファームウェアがある場合)

```
/build-flash-monitor --flash-monitor-only --port /dev/ttyUSB1
```

## 関連エージェント

このコマンドは、`m5stack_esp_idf_docs/agents/build_flasher.md`に定義されている`build-flasher`エージェントを呼び出します。
